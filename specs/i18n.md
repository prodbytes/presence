# Languages

The app speaks **English**, **Spanish** (Español) and **Portuguese**
(Português, Brazilian), picked in Settings or following the device.

## Picking the language

- **Settings → Language** (`language-picker`), after History: **Same as
  the device** (the default), **English**, **Español** or **Português**,
  each named in its own language. The app switches at once, every screen.
- Same as the device: the device's language if it's one of the three
  (any region: `es_MX`, `pt_PT`…), otherwise English.
- Kept per device with the other settings, as `language: {code}` (`en`,
  `es` or `pt`; left out for the device's), so it's backed up and restored
  like them ([Configuration](configuration.md)). An unknown code reads as
  the device's.
- Material's own texts (date pickers, tooltips of standard buttons, text
  selection) follow it too (`GlobalMaterialLocalizations`).

## The bundles

- Flutter's `gen_l10n` ([l10n.yaml](../presence_app/l10n.yaml)): the
  messages in ARB bundles, `app_en.arb` (the template, with each message's
  description and placeholders), `app_es.arb` and `app_pt.arb`, generated
  into `lib/l10n/gen/` (`AppLocalizations`, checked in; `flutter pub get`
  and builds generate it again).
- **Each area of the app has its own fragment** in
  [lib/l10n/parts/](../presence_app/lib/l10n/parts) (`core`, `settings`,
  `auth`, `events`, `home`; `<area>_<lang>.arb`), with keys prefixed by
  area. [scripts/l10n-merge.py](../scripts/l10n-merge.py) merges them into
  the three bundles and fails if a key is defined twice, or English has
  one another language lacks (or the other way round). After editing a
  fragment: `python3 scripts/l10n-merge.py && (cd presence_app && flutter
  gen-l10n)`.
- Widgets read them as `context.l10n.<key>`
  ([lib/l10n/l10n.dart](../presence_app/lib/l10n/l10n.dart)), which falls
  back to English where no localizations are set up (a widget alone in a
  test), so text never goes missing.
- Counts and values use ICU placeholders and plurals (`{count, plural,
  =1{1 day} other{{count} days}}`).

## What's translated, and what isn't

- Translated: everything the app shows: screens, buttons, tooltips,
  labels, hints, dialogs, snack bars, status lines, the health panel and
  connectivity checks, screen-reader labels.
- **Stored data isn't**: events keep the English title and detail they
  were recorded with (records and sync are unchanged); the cards, the
  player and lists show them in the language picked, worked out from the
  event's type (`AppEvent.displayTitle`), falling back to the stored text.
- Left in English: log lines (the Log tab is diagnostics), technical
  causes from AWS or HTTP (shown inside translated sentences), Google
  sign-in's own error texts in misconfigured builds, IDs, names of brands
  and services (Presence, Premium, Google, AWS, RBACR, OpenStreetMap),
  units and number formats ("30 min", "±12 m"), subject names and object
  tags (data). Settings' note under the picker says names, tags and device
  IDs show as written.
- **Unit-tested helpers keep their English**: functions that build text
  (`formatKeep`, `describeAge`, `Connectivity.of`, `SystemHealth.statusOf`,
  `PlanNotice.planText`, `VideoClip.status`…) take an optional
  `AppLocalizations` and give English without it; the widgets pass theirs.
- Errors raised in English by the code (a pasted position that can't be
  read, a camera that can't open) are translated where they're shown, by
  their known English text; anything else shows as raised.
- The **barrel roll** search also answers "haz un barrel roll" and "faça
  um barrel roll" (or "faca"), in any language.
- Portuguese plurals say "0 dispositivos" (CLDR's "one" includes 0 there).

## Size

513 messages in each language (core 7, Settings 111, account and
consent 100, events and clips 118, home, camera, health, Log and Help
177), externalized from about 50 files.

## Verified

- `i18n_test.dart`: the setting's round-trip, the device's by default, an
  unknown code ignored; picking Español, Português and English in Settings
  switches its texts; every bundle has every message, none empty, with
  the same placeholders as English; English without localizations.
- **At 320 dp in Spanish and Portuguese** (`i18n_test.dart`): the whole
  app, signed in, every tab scrolled to its end, without an overflow or
  error. It found the Help tab's title too long beside the app bar's
  buttons: the title now shrinks with an ellipsis (any language), and is
  "Ayuda" / "Ajuda".
- `event_titles_l10n_test.dart`: an event's shown title and detail equal
  the stored text in English, and are translated in Spanish and
  Portuguese; search matches both.
- Every other test runs in English, with the English texts unchanged
  (873 tests, all passing).
